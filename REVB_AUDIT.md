## What was verified independently (bit-exact unless stated)

1. **Exact KT, both alphabets.** Engine CLI output vs `audit/ref_kt.py` on
   hand-built and 70,000/50,000-byte xorshift fixtures: `L_bits`, `A_bits`,
   `L_ML_bits` bit-identical at every checkpoint × order (k 0..16). Python
   `math.log2` and the frozen libm `log2` agreed to the bit, so the ML
   recurrence was compared bit-exactly (stronger than the 1e-11 tolerance in
   the core's own suite).
2. **128-bit contexts.** S=256 fixture whose 16-byte histories share their
   most-recent 8 bytes (low 64 key bits) but differ in the older 8 bytes, with
   opposed continuation biases. Engine matched the exact reference bit-for-bit
   and its depth-16 loss differs from the 64-bit-truncated analogue — high
   key bits are live.
3. **Startup.** n=1: `L[k]=5.0` exactly for all 17 orders, `A=[+0.0]*17`.
   i<k events cost exactly log2(S) and do not touch shorter rows (tiny
   fixtures, checkpoints at n=1,2,3,5).
4. **Checkpoints / input order.** Multi-checkpoint surfaces (incl. n=1, 63,
   65535, 65536, 65537) bit-identical to input-ordered reference accumulation;
   snapshot is after scoring/updating the nth symbol. Invalid checkpoint lists

5. **Forced disk spill equivalence.** 3-page vs 512-page cache (S=32, 3,130

6. **Chunk boundaries.** 70,000-byte fixture crossing the 64 KiB input chunk

## Findings

**Code bugs: none.** The two failures encountered during the audit were bugs
in the auditor's own check scripts, fixed and re-run: (a) a G3 structural
check whose `elif` chain misclassified valid controller bytes; (b) a B5
structural check that re-segmented the shuffled draw even though the frozen
rule segments B1 once and shuffles within those units (moved terminator bytes
legitimately change B5's raw boundaries). Neither implicates the engine,
generator, or published corpora. No measured surfaces exist yet, so no
finite-sample-reader-vs-code-bug distinction arose; contrary-to-prediction
curves were neither observed nor required.

**Non-blocking observations:**

- `scripts/run_track_a.py` reuse check validates `checkpoint_count == 12` but
  not the checkpoint n-values of a reused result (all 90 frozen runs share the
  same 12 checkpoints; nit in the explicit-reuse path only).
- `REVB_FREEZE.json` `track_B.source_manifest_sha256` is still `null`. The
  Track B provenance exists (`trackb_corpora/SOURCES.md` sha256 `87d7fefb…`,
  `draw_manifest.json` sha256 `ec22d96e…`) but no execution supplement binds
  it yet, so B sidecars cannot be written honestly. This blocks B **scoring**
  at the binding step exactly as both handoffs state; it does not block A.

**Not verified by this audit (honest scope):**

- Injected ENOSPC/short-write fault paths (also unverified by the core
  handoff; guards exist in source but no fault injection was run here).
- Full 2^23-scale timing/RSS/disk envelope (that is the production
  measurement itself; CORE_HANDOFF's ~73.3 GB loose B-store bound is
  unmeasured by design).
- Re-download of the three upstream Track B sources (raw downloads were not
  retained by design; draws verified via published hashes, transform
  re-derivation, and read-only review of the frozen extraction scripts, which
  implement the declared policies: CHILDES @ID adult-role main tiers only,
  Wikipedia ns=0 non-redirect prose, kernel `*.c` path-sorted concatenation).
